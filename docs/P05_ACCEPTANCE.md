# P05 — базове приймання

Обсяг: gate prompts/05-progress-checkpoints.md на наявному js-01, Edge desktop. Продуктове тестування знову дозволено прямим дорученням користувача. P06 у цьому кроці не починали.

| Критерій | Доказ у tests/e2e/progress.spec.ts |
|---|---|
| Змінений код переживає reload | Автозбереження, reload, успішний Check відновленого коду |
| Завершення тільки після актуального Check | Starter падає; до Check завершення недоступне; редагування скасовує можливість завершення; новий Check дозволяє checkpoint |
| Завершення переживає reload | Completed UI і persisted checkpoint після перезавантаження |
| Fork не змінює основний checkpoint | Редагування fork, очікування запису, точне порівняння checkpoint до/після |
| Несумісна версія не перезаписується мовчки | Version 99 блокує editor; скасування modal зберігає record; підтвердження відновлює starter v1 та показує архів старої версії |
| Інша вкладка не губить новіший код | Застаріла вкладка отримує конфлікт; persisted код новішої вкладки збережено |

Результати: 65 unit passed; три нові desktop E2E сценарії пройшли адресними запусками. Адресний ESLint, typecheck, Prettier, diff check пройшли. E2E використовували останню успішну production-збірку того самого app-коду з попереднього кроку; застосунок цього кроку не змінювали, тому повторний build не потрібен.

Проміжні падіння тестів: неточний текст кнопки recovery та очікування LF при CRLF у Monaco Windows. Виправлено тестові fixtures/locators, повторні відповідні сценарії пройшли. Це не виправлення дефектів застосунку.

Висновок: базові критерії P05 для js-01 підтверджені. Це не повний аудит усіх додаткових можливостей P05 і не release readiness. Не перевірено upgrade старих баз, quota/transaction failure injection, malformed quiz, paging/restore learning-backups, JSON import edge cases, Firefox/Safari, mobile і повний історичний E2E-набір. Старі workspace E2E містять очікування текстів P04; перед повним regression їх слід узгодити з поточним UI. Ризики runner P03 залишаються release blockers.

Успадкування між різними уроками ще не реалізовано; для переходу до js-02 потрібен окремий інтеграційний зріз із checkpoint js-01. Це вимога cumulative продукту, яка не доводиться нинішнім single-lesson gate. Auth, cloud sync, додаткові quiz import/manual backups не входять у базове приймання P05.
