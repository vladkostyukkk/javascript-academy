# JavaScript Academy

Українськомовна платформа для вивчення JavaScript через один накопичувальний проєкт **FocusBoard**. Готові 20 із 60 уроків, Monaco з ізольованими Run/Check, локальне збереження прогресу та перенесення власного проєкту між уроками. Перші два модулі пройшли приймання. [P06](docs/P06_ACCEPTANCE.md) · [P07](docs/P07_ACCEPTANCE.md) · [Стан проєкту](docs/STATE.md)

## Локальний запуск

Потрібні Node.js 22.12+ у гілці 22, гілка 24 або 26+ та npm. Рекомендоване перевірене середовище — Node.js 24.20.0; діапазон узгоджено з Vitest і браузерними інструментами.

```sh
npm ci
npm run dev
```

Відкрийте `http://127.0.0.1:3000`. Шрифти постачаються локально з npm-пакетами; застосунок не завантажує їх із Google Fonts.

- `/` — огляд навчального шляху та майбутнього FocusBoard.
- `/course/javascript` — усі 60 уроків із маніфесту, пошук, розгортання модулів і локальні позначки завершення для поточної версії доступних матеріалів.
- `/learn/javascript/js-01` — теорія, три запитання, Monaco з файлами, Run/Check, консоль, preview, підказки та reset із підтвердженням.
- `/learn/javascript/js-02` — «let і const»: відкривається після завершення js-01 і продовжує власний checkpoint FocusBoard.
- `/learn/javascript/js-03` — «Рядки»: категорія та підпис задачі, продовження checkpoint js-02.
- `/learn/javascript/js-04` — «Числа»: обчислення загальної тривалості двох справ після js-03.
- `/learn/javascript/js-05` — «Булеві значення»: прапорці завершення/важливості та текстовий статус після js-04.
- `/learn/javascript/js-06` … `js-10` — порівняння, арифметика, шаблонні рядки, перетворення типів і підсумковий preview; пакети пройшли приймання P06, доступ залежить від завершення попереднього уроку.
- `/learn/javascript/js-11` … `js-20` — умови, функції, валідація назви та незалежні генератори ID. Кожний урок продовжує попередній checkpoint.
- `/learn/javascript/js-21` … `js-60` — заплановані уроки зі станом блокування.
- `/project` — ілюстрація майбутнього проєкту й фактична локальна історія checkpoint-ів із завантаженням JSON.
- `/lab/runner` — локальна лабораторія P03: pure JS, DOM, ES modules, mock fetch та діагностичні сценарії. Запуск, зупинка, консоль і результат працюють; навчальний прогрес не змінюється.

Після quiz редагуйте `src/app.js`. HTML і CSS доступні для читання. «Запустити» показує фактичний вивід у консоль, а «Перевірити» оцінює поведінку за умовами поточного уроку. Ctrl+Enter — Run, Ctrl+Shift+Enter — Check. Зміна коду скасовує старі результати. Файли автоматично записуються в IndexedDB після 500 ms без змін. Перед виходом дочекайтеся статусу збереження. Після успішного Check натисніть «Завершити урок і зберегти checkpoint». Статус completed і точні перевірені файли записуються разом. Редагування, новий Run/Check, помилка або конфлікт не дозволяють завершити урок зі старим результатом. Після завершення js-01 перейдіть до js-02 кнопкою наступного уроку. Нова чернетка успадковує ваш код, а наявна зберігається. За несумісності основи можна явно підтвердити офіційний starter, зберігши попередній checkpoint.

Збережене завершення відображається після reload. Для подальшого редагування відкрийте повторення в окремій копії: перша копія починається зі starter, наступні відкриття продовжують її чернетку. Повторний Check і reset не змінюють основного checkpoint. Повернення до завершеного уроку доступне після збереження коду й навчального стану копії; reload повертає до основного уроку, звідки можна знову відкрити повторення. Результати Check, cursor та undo після reload не відновлюються. Reset потребує підтвердження.

Відповіді, факт перевірки quiz, кількість quiz-спроб і вкладка зберігаються після 400 ms без змін окремо для main/fork та версії матеріалів. При відкритті відповіді заново оцінюються поточним quiz; збережений запис не може самостійно відкрити практику без правильних відповідей. Пошкоджений стан можна явно відновити з архівуванням; це не скидає код або checkpoint. Конфлікт між вкладками зупиняє запис і дозволяє завантажити відповіді перед reload. На карті позначка «Завершено» й лічильник беруться лише з валідної пари checkpoint/completed поточної версії; помилка читання показується окремо від нульового прогресу. Дані перечитуються при поверненні фокуса до сторінки.

При конфлікті з іншою вкладкою автозбереження зупиняється: завантажте JSON-копію поточного коду перед reload. Для пошкодженої або несумісної чернетки доступне явне відновлення зі starter; попередній запис архівується в тій самій транзакції. JSON-копія — резервні дані, не готовий експорт FocusBoard; сумісну чернетку можна імпортувати після reload через блок резервних копій. Дані прив’язані до origin і профілю браузера; очищення даних сайту видаляє їх. При недоступному сховищі початкове відкриття редактора блокується з можливістю повторити спробу, щоб не підмінити непрочитану чернетку starter-ом.

У практиці блок **«Резервні копії файлів»** дозволяє вручну створити копію збереженої чернетки, переглянути архів цього уроку, прочитати файли як текст і завантажити JSON. Список показує main/fork записи сторінками по 20. Сумісну копію можна відновити після підтвердження: поточна чернетка архівується в тій самій транзакції, а попередній Check скасовується. Незбережені редагування спочатку мають завершити autosave. Копії іншої версії матеріалів або зі зміненою read-only основою не підставляються автоматично. Завершений main не перезаписується — відкрийте повторення; там доступні також копії основного уроку. Це архів файлів, не quiz: learning-backups доступні окремо у вкладці «Теорія»: перегляд відповідей, JSON і відновлення після підтвердження. Відновлення архівує попередній стан і заново оцінює quiz; код і checkpoint не змінюються. Копії фільтруються за уроком, версією та режимом main/fork. Браузерні перевірки цієї частини P05 також відкладено.

У цьому ж блоці **«Імпорт JSON-копії»** приймає файл чернетки або запису файлового архіву розміром до 2 MiB. Вибір файла лише відкриває текстовий перегляд; заміна потребує окремого підтвердження. Перевіряються формат, урок, версія матеріалів, шляхи, незмінність read-only файлів і ліміти коду (64 KiB на файл, 256 KiB разом). Поточна чернетка архівується атомарно із записом імпортованої; конфлікт з іншою вкладкою скасовує заміну. Потрібен новий Check. Імпорт не виконує код, не переносить completed/checkpoint або quiz і не відкриває наступний урок. Основний завершений урок захищений: імпортуйте файли в повторення. Дані вибраного файла не надсилаються на сервер. Цей сценарій ще не перевірено поведінково.

IndexedDB v3 додає learning-sessions/learning-backups, не змінюючи drafts, draft-backups, checkpoints, progress і forks попередніх версій. Якщо оновлення блокує стара вкладка, закрийте її та повторіть завантаження. Формати попередніх snapshots залишаються v1. Імпорт використовує наявні stores без міграції. Деталі — ADR-014–017 у `docs/DECISIONS.md`.

Прототип не готовий до публічного виконання довільного коду. Підтверджені межі: hostile DOM-цикл блокує вкладку; self-navigation iframe може створити мережевий запит. Повний опис, результати тестів і release blockers — у [docs/P03_RUNNER.md](docs/P03_RUNNER.md).

## Перевірки

Нижче — доступні команди, а не обов’язковий пакет після кожної зміни. Вибір за ризиком і адресні приклади — у [docs/QUALITY.md](docs/QUALITY.md). Чинні результати продуктових тестів записані в [docs/STATE.md](docs/STATE.md); зміна агентної документації не потребує build/unit/E2E.

```sh
npm run lint
npm run format:check
npm run typecheck
npm run validate:content
npm test
npm run build
npm run test:e2e
```

Playwright сам запускає production-сервер на **3100**, не перевикористовує інший сервер і зупиняє його після тестів. Перед тестуванням після змін виконайте `npm run build`; порт 3100 має бути вільним. На Windows тести використовують встановлений Microsoft Edge; на інших системах спочатку виконайте `npx playwright install chromium`. Три профілі: desktop, tablet, mobile; окремий mobile-сценарій перевіряє ширину 320 px. Авторський тест еталона запускається в desktop-профілі. Автоматичні перевірки axe не замінюють ручного аудиту доступності.

`validate:content` виконується автоматично перед build. Він перевіряє metadata, передумови, Markdown, quiz, файли та checksum; поведінка еталона перевіряється окремо через Playwright sandbox. Формат пакета описано в `docs/LESSON_CONTRACT.md`. Матеріали `content/` виключені з автозаміни форматування та Next.js lint, щоб не змінювати навчальний код і checksum.

`npm run build:runner` збирає TypeScript bootstrap у згенерований `public/runner/runtime.js` (Git ignore). Команда автоматично виконується перед `dev` і `build`; після зміни `lib/runner/runtime.ts` під час відкритого dev-сервера запустіть її повторно. Runtime виконується тільки в opaque sandbox. Runner security-тести — desktop; навмисний DOM-цикл тестується в окремому браузері із зовнішнім watchdog і teardown.

`npm run build:editor` збирає локальні Monaco ESM assets і language workers у `public/monaco/`, також автоматично перед dev/build. Після зміни `lib/workspace/editor-entry.ts` повторіть команду. CDN не потрібен; при помилці завантаження доступні простий редактор і retry зі збереженням поточної чернетки. Декларативні checks відкриті для клієнта, але reference solution не постачається у файлах редактора. Рішення P04 і patch override DOMPurify описано в ADR-011/012.

Для production-перегляду: `npm run build`, потім `npm run start`.

## Основа інтерфейсу

Next.js App Router + TypeScript, Tailwind CSS, локально адаптовані компоненти shadcn/ui Button і Tabs на Radix. Дизайн-токени знаходяться в `app/globals.css`, налаштування компонентів — у `components.json`. Структура лишається узгодженою з `docs/ARCHITECTURE.md`.

Документація базового налаштування: [Next.js](https://nextjs.org/docs/app/getting-started/installation), [shadcn/ui](https://ui.shadcn.com/docs/installation/manual).

## Початковий пакет планування та наступні сесії

1. Відкривай Codex із кореня цього репозиторію. Приватний GitHub-репозиторій: `https://github.com/vladkostyukkk/javascript-academy`; основна гілка `main`, remote `origin`. Поточний коміт перевіряй через `git log -1`.
2. Для продовження прочитай `docs/STATE.md` за [prompts/RESUME.md](prompts/RESUME.md) і виконай наступне доручене підзавдання; додаткове повідомлення з дозволом після огляду не потрібне. Для точної локальної правки не завантажуй весь фазовий контекст.
3. Обирай релевантні розділи через AGENTS.md. Фазові prompts описують обсяг/gate, а не наказ повторити готові P00–P04. Не запускай усі фази одночасно.
4. Оновлюй STATE після значущого результату, блокера або handoff; історію файлів зберігає Git. Коміт/push — у межах явного доручення.

Два проєктні skills: [academy-lesson-development](.agents/skills/academy-lesson-development/SKILL.md) для матеріалів/cumulative checkpoints і [academy-code-execution](.agents/skills/academy-code-execution/SKILL.md) для editor/runner/checker. Вони посилаються на наявні контракти й завантажують деталі за потреби. Для звичайного debugging використовуйте REPAIR.md; загальні системні skills не копіюються в проєкт.

Приклад початку сесії: «Продовжуй наступну дію з docs/STATE.md за AGENTS.md. Продуктові тести поки не додавай і не запускай». Це зберігає поточне тимчасове обмеження, а не робить його постійним правилом якості. Результат аудиту процесу — [docs/WORKFLOW_AUDIT.md](docs/WORKFLOW_AUDIT.md).

## Файли, які зберігають контекст

- `AGENTS.md` — короткі постійні правила для Codex.
- `docs/PRODUCT.md` — навіщо існує продукт і його межі.
- `docs/ARCHITECTURE.md` — архітектурні та security-рішення.
- `docs/LESSON_CONTRACT.md` — формат уроку та вимоги до перевірок.
- `docs/CURRICULUM.md` + `curriculum/manifest.json` — всі 60 уроків і практичні цілі.
- `docs/ROADMAP.md` — порядок роботи та приймальні критерії.
- `docs/STATE.md` — актуальна стадія, проблеми, наступна дія.
- `docs/DECISIONS.md` — журнал ухвалених рішень.
- `prompts/` — завдання по фазах.

## Основний принцип

Ні `AGENTS.md`, ні довжина чату не гарантують пам’яті. Стан проєкту має бути записаний у файлах і підтверджений комітами та тестами. Не змушуй Codex генерувати всі 60 уроків за один запит.
