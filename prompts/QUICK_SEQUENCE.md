# Suggested Codex sequence

1. `00-discovery.md` — read-only plan. Review architecture.
2. `01-app-shell.md` — proper UI shell.
3. `02-lesson-registry.md` — content engine & first lesson.
4. `03-runner-spike.md` — hardest technical risk; do not proceed until verified.
5. `04-workspace-checker.md` — functional editor / tests / preview.
6. `05-progress-checkpoints.md` — preserve learner code.
7. `06-lessons-01-10.md` ... `11-lessons-51-60.md` — use academy-lesson-development for the next bounded cumulative slice; choose scope by dependencies and verification needs, not a fixed batch size. Do not generate the whole course automatically.
8. `12-release-audit.md` — tests + deploy readiness.
9. `13-auth-sync-optional.md` — ONLY after approval, if needed.

Це карта порядку фаз, не список для повторного виконання. Для нової сесії достатньо доручити: «Продовжуй з наступної дії docs/STATE.md за AGENTS.md», додавши поточні обмеження. RESUME.md пояснює цей процес і не вимагає другого повідомлення з дозволом на вже доручену роботу. Для конкретної локальної зміни одразу назви результат і відповідний файл/симптом. REPAIR.md — для помилок; REVIEW.md — лише огляд.
